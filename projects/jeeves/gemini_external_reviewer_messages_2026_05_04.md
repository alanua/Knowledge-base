## 5. Accepted Design Points

- Gemini can be modeled as an external reviewer / auditor node for deep-context review, long-context analysis, multimodal review, private-memory triage, security audit, red-team architecture review, and localization review.
- Gemini output must return to the ChatGPT exoskeleton for classification, filtering, canon gating, and presentation to Oleksii.
- Intake packets should include bounded metadata, confirmed canon, evidence, draft artifact, exact questions, forbidden actions, response format, target language, and a system-state snapshot.
- Output should include summary, strong points, risks, missing context, privacy notes, canon drift warning, redacted entity categories, candidate constraints/findings/changes, recommended route, and confidence.
- NotebookLM/Drive handling should default to a pull-only packet model. Direct access, if ever authorized, must be read-only and must produce evidence, not canon.
- Gemini should not assume context outside the provided packet. Missing context should be reported rather than invented.
- Secret quarantine is required if credentials, tokens, passwords, database URIs, or equivalent live access material are detected.
- Block conditions should include missing canon for structural review, secret detection, privacy conflicts, objective conflicts with forbidden actions, execution/merge/deploy/canon-promotion requests, and insufficient evidence requiring invention.

## 7. Resulting Gemini Adapter v0.1 Candidate Contract

Status: candidate contract only; not canon.

### Authority

- Gemini is an external auditor node.
- Gemini is not an executor, manager, canon source, or autonomous tool.
- Gemini output is evidence only.
- ChatGPT classifies Gemini output before use.
- Oleksii approves merge, live access, private access, deploy, canon promotion, and any authority expansion.
- Runner remains a bounded executor and does not gain broader authority from this adapter.

### Intended Use Modes

- `PR_REVIEWER`
- `LONG_CONTEXT_ANALYST`
- `PRIVATE_MEMORY_TRIAGE`
- `MULTIMODAL_UI_REVIEWER`
- `RED_TEAM_ARCHITECT`
- `SECURITY_AUDITOR`
- `LOCALIZATION_REVIEWER`

### Intake Packet

Candidate intake schema:

```text
schema_version: gemini_adapter_v0_1
target: optional controlled Gemini auditor backend
task_id: bounded task identifier
objective: specific review objective
mode: one adapter mode
privacy_level: PUBLIC_SAFE, INTERNAL_ONLY, or STRICT_REDACTION
response_format: expected return format
target_language: expected output language
system_state_snapshot: timestamp or version reference for the supplied context
confirmed_canon: verified task rules and facts
evidence: supplied logs, docs, screenshots, notes, or issue text
draft_artifact: specific artifact to review, if any
exact_questions: bounded questions to answer
forbidden_actions: explicit actions Gemini must not take or recommend as authority
```

### Expected Output

Candidate output schema:

```text
source: gemini_auditor_node
status: success, blocked, or needs_context
summary: concise review summary
strong_points: confirmed strengths in the artifact or proposal
risks: identified risks and failure modes
canon_drift_warning: true or false
missing_context: missing evidence or canon needed for reliable review
privacy_notes: public-safety and redaction notes
redacted_entities_list: high-level redaction categories/counts when relevant
machine_readable_payload:
  findings: non-authoritative findings
  candidate_changes: non-authoritative candidate changes
  constraints: extracted constraints
recommended_route: accept, revise, block, private_triage, backlog, or reject
confidence: Gemini confidence level for the review
```

### Block Conditions

Gemini should block or recommend rejection when:

- Confirmed canon is missing for a structural review.
- Secrets, credentials, tokens, passwords, private keys, database URIs, or equivalent live access material appear in the packet.
- Privacy level conflicts with a requested public output.
- Objective conflicts with forbidden actions.
- The request asks Gemini to execute, merge, deploy, promote canon, control a runner, write directly to the repository, or expand its own permissions.
- Evidence is insufficient and a response would require inventing missing facts.

### NotebookLM / Drive Handling

- Default model: pull-only packet assembled by the ChatGPT exoskeleton or a designated safe process.
- Direct NotebookLM/Drive access, if ever authorized, must be read-only.
- Extracted material remains evidence until the ChatGPT exoskeleton classifies it and Oleksii approves any canon promotion.
- Private sources may be used only in private triage mode.
- Raw private material must not be copied into public GitHub.

### Non-Authorizations

This candidate contract does not authorize Gemini to receive or use GitHub tokens, SSH keys, server access, secrets, deployment paths, runner control, direct repository writes, merge authority, deploy authority, live system changes, canon promotion, or autonomous permission expansion.
